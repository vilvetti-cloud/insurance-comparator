# Инструкции для ИИ-агентов (Claude Code, Codex и др.)

Проект — «Страховой аналитик»: рабочее место страхового агента для сравнения условий КАСКО
11 страховых компаний по 10 параметрам на основе официальных правил страхования.

## Как устроено

- **Единственное приложение — `web_app.py` (Flask).** На Vercel оно запускается через
  `vercel_db_entry.py`, локально и через `Procfile` — как `web_app:app`. Старого `app.py` больше нет,
  не создавайте его заново.
- **Источник данных для сайта — `data/casco-comparison-master.json`** (принятый набор 110 ячеек:
  11 компаний × 10 параметров). Если файл есть, база данных сайтом не используется.
  База PostgreSQL (`DATABASE_URL`) нужна только для конвейера сбора (`collector/`, `scripts/`).
- **Логика сравнения — `core/services/sales_insights_service.py`.**
  Шаблоны — `templates/`, стили — `static/app.css`.
- **Официальные PDF правил** — `data/sources/<страховщик>/`, ссылки на оригиналы — `docs/source-urls.md`.
- Каждый пуш в `main` автоматически выкатывается в продакшен на Vercel.

## Правила сравнения — единые для всех 10 параметров

1. **Условие прямо указано в официальных правилах только одной компании — это её преимущество.**
   Отсутствие условия в принятом источнике другой компании не делает сравнение «нейтральным».
   Исключение: если у одной компании условие **прямо исключено**, а у другой не указано, —
   никто не выигрывает (оба «в минусе», исход `equal`). Исключение покрытия не бывает преимуществом.
2. **Условие указано у обеих — сравниваются значения.** Параметр задаёт только *способ чтения значения*
   (таблица `_FIELD_COMPARATORS`): сумма франшизы, порог тотала, срок выплаты, форма ремонта,
   уровень покрытия. Правила принятия решения одинаковы для всех.
   Франшиза: если размер не решает, сравнивается отмена франшизы при известном виновнике ДТП
   (`_franchise_fault_waiver`): действует по умолчанию > можно выбрать в договоре > не указано.
3. GAP, самовозгорание, терроризм и БПЛА — «параметры покрытия», читаются одинаково:
   исключено < доп. опция < включено. «Застрахован только если прямо указано в договоре» —
   это доп. опция (клиент может её получить). Шаблонное «если договором не предусмотрено иное»
   после исключения — не опция.

## Сообщение клиенту

- Сначала преимущества над конкурентом, затем остальные плюсы как бонус, в конце призыв.
  Параметры, где конкурент лучше, не упоминаются.
- Если у конкурента условие в правилах не указано или написано размыто — говорим клиенту,
  что **у конкурента этого нет** (решение владельца: на размытое условие клиент рассчитывать не может).
- Сравнение с 2–3 конкурентами (`analyze_group`, страница `compare_group.html`): каждая пара считается
  так же, как отдельно; в общем сообщении параметр упоминается, только если первая компания лучше
  хотя бы одного конкурента и ни один из выбранных конкурентов не лучше её.

Не добавляйте особые правила для отдельного параметра (например, «только для GAP»).
Если нужно новое поведение — сделайте его общим и добавьте тест, что все параметры одной группы
ведут себя одинаково (см. `UnifiedRuleTests` в `tests/test_sales_insights_service.py`).

## Проверка изменений

```bash
pip install -r requirements.txt pytest
python -m pytest -q
```

16 тестов пропускаются без PostgreSQL/Docling — в GitHub Actions они выполняются.

При любом изменении логики сравнения проверьте влияние на все пары компаний:

```bash
python scripts/compare_all_pairs.py /tmp/before.json   # на main
python scripts/compare_all_pairs.py /tmp/after.json    # на вашей ветке
python scripts/compare_all_pairs.py --diff /tmp/before.json /tmp/after.json
```

Каждое изменившееся сравнение должно быть объяснимо; перечислите их в описании PR.

## Порядок работы

- Работайте в отдельной ветке и открывайте pull request в `main`. Сливайте только после зелёных
  проверок GitHub Actions («Python tests», «CASCO document pipeline tests»).
- Пишите описание PR и общение с владельцем проекта на русском языке.
- После каждой правки давайте владельцу пошаговую инструкцию: что нужно сделать на GitHub
  (слить PR, удалить ветку и т.п.) и в настройках Vercel, чтобы изменение заработало на сайте.
- Не коммитьте `__pycache__`, `.env`, PDF в корень репозитория.

## Известные ограничения

- Ночная проверка — `source-check.yml`: `scripts/check_sources.py` (`collector/source_watch.py`)
  скачивает все файлы из `docs/source-urls.md`, сравнивает с `data/sources/` и пишет
  `data/source-check.json` (его показывает сайт); затем `scripts/auto_update.py`
  (`collector/auto_update.py`) **сам обновляет ответы**. Решение владельца от 20.10.2026: сайт
  автономный, владелец получает письмо (issue на GitHub).
  Порядок: тот же текст — только обновить копию; изменились пункты о параметре — Claude
  (`collector/answer_writer.py`, секрет `ANTHROPIC_API_KEY`) переписывает только затронутые ответы.
  Ответ принимается, только если каждая цитата дословно есть в новом тексте, каждое число
  (дни, ₽, %) есть в цитатах и после этого проходят тесты. Иначе — старый ответ, пометка и письмо.
  Неудачный файл с тем же SHA-256 повторно не разбирается (`data/auto-update-log.json`).
  Новая редакция правил часто выходит по **новой** ссылке, а старая продолжает открываться
  (так было у ВСК и Росгосстраха), поэтому проверка следит и за страницами со списком правил
  (`official_doc_urls` в `collector/registry.py`) и помечает появившиеся там документы КАСКО.
- Второй проход утром — с компьютера владельца в России (`scripts/local_check.ps1`, задача
  планировщика Windows, отдельный клон `C:/Users/Admin/insurance-comparator-auto`): перепроверяет
  компании, которые не открылись с GitHub, и берёт файлы, сохранённые вручную в папку
  «Новые правила КАСКО» на рабочем столе. Изменившийся файл отправляется в `data/incoming/`;
  этот пуш запускает `source-check.yml`, который разбирает файл на GitHub (ключ ИИ на компьютере не нужен).
- ИИ для разбора: Claude, если задан секрет `ANTHROPIC_API_KEY`, иначе бесплатный Gemini
  (`GEMINI_API_KEY`, модель — переменная `GEMINI_MODEL`); Gemini получает только страницы о параметре.
  Проверки ответа одинаковы для обоих.
- Ренессанс (иногда) и Югория закрыты от автоматических запросов (403 / проверка «не робот»).
  Не обходить защиту, притворяясь браузером: такие компании честно показываются как
  «проверьте вручную».
- Старый `daily-collection.yml` работает с базой данных и читает копию PDF из репозитория,
  поэтому изменений на сайтах не видит; сайт его результаты не использует.
- Подключение Vercel к ИИ-инструментам пока не видит команду `manager-90-plan`
  (ошибка на стороне Vercel); статус деплоя смотрите через статусы коммитов на GitHub.
