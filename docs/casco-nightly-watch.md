# Ночной контроль официальных документов КАСКО

## Что выполняет

Workflow `.github/workflows/casco-official-document-watch.yml` запускается ежедневно в 03:30 UTC и вручную через GitHub Actions.

1. Проверяет закреплённые официальные PDF и официальные страницы, на которых страховщики публикуют документы.
2. Для PDF получает текущие байты и сравнивает SHA-256 с сохранённой версией. В режиме watch локальная копия PDF намеренно не используется: иначе изменения на официальном сайте могли бы остаться незамеченными.
3. Неизменившиеся документы не отправляются на повторное извлечение фактов.
4. Для изменившегося документа запускает существующий checksum-first pipeline: извлечение текста по страницам, детерминированную проверку известных пунктов, извлечение оставшихся полей через настроенного провайдера и валидацию доказательств.
5. Сохраняет отчёт GitHub Actions artifact `casco-nightly-watch` на 90 дней.
6. Изменившиеся ссылки на официальных страницах, которые ещё не закреплены в реестре, отмечаются как кандидаты для проверки. Автоматически добавлять их в источник истины нельзя: сначала нужно убедиться, что это документ именно по КАСКО и нужной редакции.

## Что требуется для запуска

- `DATABASE_URL` в GitHub Actions secrets;
- установленная схема базы данных и доступ к ней;
- для автоматического разбора новых/изменившихся условий — доступный провайдер из поддерживаемых pipeline (Gemini, Groq, Mistral или OpenRouter). Ключ OpenAI не используется и не требуется;
- доступ GitHub Actions к официальным сайтам страховщиков.

Если источник изменился, но ни один провайдер не доступен, документ и сбой попадут в отчёт; новые неподтверждённые факты не должны считаться проверенными.

## Важное ограничение

Ночной контроль — это механизм обнаружения и повторной обработки, а не доказательство, что все 110 полей уже проверены. Первая полная эталонная база должна быть отдельно проверена по связанным пунктам и исключениям. При изменении PDF история ревизий хранится в базе, а полный отчёт — в artifact workflow.
