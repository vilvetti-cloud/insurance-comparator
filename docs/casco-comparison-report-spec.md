# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) НА ПОДГОТОВКУ ЭТАЛОННОГО АНАЛИТИЧЕСКОГО ОТЧЁТА ПО ДОКУМЕНТУ

**Универсальный шаблон для любой ИИ-системы**

**Версия:** 2.0 (с разделом 14 «Конечный ответ», единым форматом таблицы 6.2 и обновлённым чек-листом)

---

## 0. Назначение документа

Настоящее ТЗ описывает **полный, самодостаточный процесс** подготовки аналитического отчёта по произвольному нормативному документу (правила страхования, договор, регламент, инструкция) на основе заданного перечня вопросов.

**Главное требование:** отчёт должен быть **самодостаточным** — читатель, открывший его, получает полный ответ по каждому вопросу **без обращения к исходному документу** и **без уточняющих вопросов**.

Для этого ТЗ содержит:
- требования к входным данным;
- трёхуровневый перечень вопросов (A/B/C) с указанием, что попадает в таблицу, а что — в текст;
- правила анализа, исключающие типовые ошибки;
- обязательные блоки ответа по каждому параметру;
- **единый формат таблицы сравнения (6.2, 6 столбцов);**
- **образец конечного ответа (раздел 14);**
- чек-листы самопроверки;
- формат вывода и шаблоны формулировок.

---

## 1. Входные данные

### 1.1. Обязательные

- **Файл документа** (PDF, DOCX, TXT или иной машиночитаемый формат).
- **Название документа** и, если применимо, редакция/дата вступления в силу.
- **Перечень вопросов** (см. раздел 3). Если перечень не задан — использовать типовой из раздела 3.

### 1.2. Опциональные

- Контекст: для какой цели готовится отчёт (юридическая проверка, сравнение, клиентская консультация).
- Ограничения: только текст документа, без внешних источников.

### 1.3. Требования к читаемости

Если PDF содержит технические артефакты (битые символы, наложения), ИИ обязан:

- игнорировать артефакты, не несущие смысла;
- не делать выводов на основе повреждённого текста;
- при необходимости указывать: «фрагмент текста нечитаем, вывод сделан по сохранившейся части».

## 2. Методология анализа

### 2.1. Принцип «только текст документа»

ИИ отвечает **исключительно на основе загруженного документа**. Внешние знания, другие редакции, судебная практика и общие представления о «стандартных» условиях не используются.

### 2.2. Различение уровней регулирования

Каждый ответ должен быть отнесён к одному из уровней:

| Уровень | Как обозначать |
|---|---|
| Прямо предусмотрено документом | «Предусмотрено» + пункт |
| Отнесено к другому документу (договору, полису, приложению) | «Определяется Договором» + указание, что именно |
| Прямо исключено | «Исключено» + пункт |
| Не упомянуто | «Прямо не упомянуто» + анализ ближайших по смыслу пунктов |
| Противоречие внутри документа | «Внутреннее противоречие» + оба пункта |

### 2.3. Работа с «молчащими» пунктами

Если вопрос не имеет прямого ответа:

1. Найти ближайшие по смыслу пункты (покрытие, исключение, ограничение).
2. Указать, что прямого ответа нет.
3. Не делать вывод «покрывается по умолчанию» и не делать вывод «исключено по умолчанию».
4. Дать корректную формулировку: «Прямо не упомянуто; решение зависит от обстоятельств и условий Договора».

**Стандартная формулировка для «молчащего» пункта:**

> «Прямо не упомянуто. Ближайшие по смыслу пункты: [ссылки]. Автоматическое покрытие (или исключение) не подтверждено. Решение зависит от обстоятельств события и условий Договора.»

### 2.4. Работа с отсылками

Если документ отсылает к Договору, закону или иному акту:

- указать это;
- не подменять содержание отсылки своими предположениями;
- отметить, что параметр определяется соответствующим документом.

### 2.5. Точность формулировок

- Использовать формулировки, близкие к тексту документа (особенно для порогов, сроков, лимитов).
- Различать «превышает», «равно или превышает», «не менее», «не более».
- Различать «страховая сумма», «страховая стоимость», «действительная стоимость».
- Различать «риск» и «страховой случай».
- Различать «рабочие» и «календарные» дни.

### 2.6. Ссылки на пункты

Каждое утверждение сопровождается ссылкой в формате:

- «п. X.Y»
- «п. X.Y.Z»
- «пп. X–Y»
- «подп. N п. X.Y»

## 3. Перечень вопросов и его уровни

### 3.0. Назначение перечня и принцип уровней

Перечень вопросов **не означает, что все вопросы должны попасть в таблицу сравнения**. Перечень — это каркас полноты. Он разделён на три уровня:

| Уровень | Назначение | Куда попадает | Объём |
|---|---|---|---|
| **A. Ключевые параметры** | Основа таблицы сравнения | Только в таблицу сравнения | 10 параметров |
| **B. Существенные условия** | Полный отчёт, практические условия | В текстовую часть отчёта | ~52 вопроса |
| **C. Справочные условия** | Полнота отчёта | В текстовую часть отчёта | ~50 вопросов |

**Правила использования уровней:**

1. **Уровень A** — обязателен для таблицы сравнения. Именно эти 10 параметров образуют строки таблицы.
2. **Уровень B** — обязателен для полного отчёта. В таблицу **не попадает**.
3. **Уровень C** — обязателен для полного отчёта. В таблицу **не попадает**.
4. Если задача — **быстрая справка**, допускается ответ только по Уровню A.
5. Если задача — **полный отчёт**, отвечать нужно на A + B + C, но таблица строится **только из A**.

**Запрещено:**

- впихивать в таблицу параметры из уровней B и C;
- отвечать только на «удобные» вопросы, пропуская остальные;
- считать, что весь перечень вопросов = строки таблицы.

## 4. Правила формирования ответов

### 4.1. Структура каждого ответа

Каждый ответ должен содержать:

1. **Прямой ответ** (одно предложение).
2. **Суть условия** (механизм).
3. **Числовые параметры** (сроки, проценты, лимиты).
4. **Условия применения**.
5. **Ограничения и исключения**.
6. **Отсылки к Договору**.
7. **Отсылки к закону**.
8. **Ссылки на пункты**.
9. **Уровень определённости**.

### 4.2. Шаблоны формулировок

**Прямое покрытие:**

> «Предусмотрено. [Условие]. Ограничения: [перечень]. Пункты: [ссылки].»

**Определяется Договором:**

> «Предусмотрено как механизм, конкретные параметры определяются Договором. [Что именно определяется]. Пункты: [ссылки].»

**Прямое исключение:**

> «Исключено. [Формулировка исключения]. Применяется, если иное не предусмотрено Договором. Пункты: [ссылки].»

**Не упомянуто:**

> «Прямо не упомянуто. Ближайшие по смыслу пункты: [ссылки]. Автоматическое покрытие (или исключение) не подтверждено. Решение зависит от обстоятельств события и условий Договора.»

**Внутреннее противоречие:**

> «В документе есть расхождение: п. X говорит [А], п. Y говорит [Б]. Для корректного вывода необходимо [уточнение].»

### 4.3. Запрещённые формулировки

- «Скорее всего, покрывается».
- «Обычно так и бывает».
- «По стандартным правилам».
- «Как правило, суды...».
- Любые утверждения без ссылки на пункт.
- Подмена «не упомянуто» на «исключено» или «покрыто».

### 4.4. Точность по числам и срокам

- «Более 75%» ≠ «75% и более».
- «Не более 25%» ≠ «25%».
- «30 рабочих дней» ≠ «30 календарных дней».
- «С даты предоставления документов» ≠ «с даты обращения».
- «После получения результатов диагностики» ≠ «с момента обращения».

## 5. Обязательные блоки ответа (для каждого параметра)

Каждый ответ по каждому параметру **обязан** содержать следующие блоки. Если блок неприменим — писать «Не применимо» или «Не установлено», но **не пропускать**.

### 5.1. Блок 1. Прямой ответ

Одно предложение: «Предусмотрено» / «Не предусмотрено» / «Прямо не упомянуто» / «Определяется Договором» / «Исключено».

### 5.2. Блок 2. Суть условия

Развёрнутое описание механизма: что предусмотрено, как работает, в каких границах. 2–5 предложений, близко к тексту.

### 5.3. Блок 3. Числовые параметры

Все числа, сроки, проценты, лимиты, пороги. Если чисел нет — «Числовые параметры в документе не установлены».

### 5.4. Блок 4. Условия применения

При каких обстоятельствах параметр применяется. Если условий нет — «Применяется без дополнительных условий».

### 5.5. Блок 5. Ограничения и исключения

Что **не** покрывается, изъятия, оговорки, запреты. Перечень. Если ограничений нет — «Ограничения не установлены».

### 5.6. Блок 6. Отсылки к Договору

Что именно определяется Договором. Если отсылок нет — «Определяется только документом».

### 5.7. Блок 7. Отсылки к закону

Ссылки на законы, прямо упомянутые в документе. Если отсылок нет — «Отсылки к закону отсутствуют».

### 5.8. Блок 8. Ссылки на пункты документа

Точные ссылки. **Обязателен всегда.**

### 5.9. Блок 9. Уровень определённости

Одна из четырёх пометок:

- «Прямо предусмотрено»
- «Определяется Договором»
- «Прямо не упомянуто»
- «Прямо исключено»

### 5.10. Блок 10. Примечание (опционально)

Внутреннее противоречие, неоднозначность, спорная формулировка.

## 6. Структура таблицы сравнения

### 6.1. Единый формат таблицы: 6 столбцов

**Настоящее ТЗ использует только один формат таблицы — сокращённый (6 столбцов).** Полный формат (11 столбцов) **не применяется**, чтобы избежать разнобоя.

| № | Параметр | Прямой ответ | Ключевые условия | Числовые параметры | Ограничения | Ссылки на пункты |
|---|---|---|---|---|---|---|
| 1 | Франшиза | | | | | |
| 2 | Ремонт без справок | | | | | |
| … | … | | | | | |

**Для сравнения двух документов** столбцы дублируются:

| № | Параметр | Прямой ответ — Док. 1 | Прямой ответ — Док. 2 | Ключевые условия — Док. 1 | Ключевые условия — Док. 2 | Числовые — Док. 1 | Числовые — Док. 2 | Ограничения — Док. 1 | Ограничения — Док. 2 | Ссылки — Док. 1 | Ссылки — Док. 2 |
|---|---|---|---|---|---|---|---|---|---|---|---|

Если таблица из 12 столбцов неудобна — допускается **две отдельные таблицы**: сначала по Документу 1, затем по Документу 2, с одинаковым набором строк.

### 6.2. Правила заполнения ячеек

- В каждой ячейке — **только та информация, которая относится к столбцу**.
- Не дублировать содержимое между столбцами.
- Если данных нет — писать «Не установлено», «Не применимо», «Определяется Договором».
- Пустых ячеек быть не должно.
- Ответ не может быть сведён к одной фразе «Да» или «Предусмотрено». Минимум — прямой ответ + одно ключевое условие + ссылка.

### 6.3. Соотношение уровней и таблицы

- В таблицу попадают **только параметры Уровня A**.
- Параметры Уровней B и C **в таблицу не попадают**.
- Если в таблице оказался параметр из B или C — это ошибка структуры.

## 8. Чек-лист самопроверки перед выдачей отчёта

### 8.1. Полнота

- [ ] Ответы даны на **все** вопросы из разделов 3.A, 3.B, 3.C.
- [ ] По каждому вопросу указан пункт документа.
- [ ] Указаны ограничения и исключения.
- [ ] Указаны сроки, лимиты, пороги — с точными формулировками.
- [ ] По каждому параметру таблицы перечислены **все ограничения** из соответствующего пункта.

### 8.2. Корректность

- [ ] Нет утверждений без ссылки на пункт.
- [ ] Нет подмены «не упомянуто» на «исключено» или «покрыто».
- [ ] Различены уровни: документ / Договор / закон.
- [ ] Различены «риск» и «страховой случай».
- [ ] Различены «страховая сумма» и «страховая стоимость».
- [ ] Различены «рабочие» и «календарные» дни.
- [ ] Числа и сроки приведены точно.

### 8.3. Работа с «молчащими» пунктами

- [ ] По каждому «молчащему» пункту указано, что прямого ответа нет.
- [ ] Дана корректная формулировка «зависит от обстоятельств и Договора».
- [ ] Не сделано ложных выводов в обе стороны.

### 8.4. Блоки ответа

- [ ] В каждом параметре заполнены **все 9 обязательных блоков** (5.1–5.9).
- [ ] Нет пустых ячеек в таблице — вместо них «Не установлено» / «Не применимо».
- [ ] Числовые параметры выделены в отдельный столбец.
- [ ] Ограничения выделены в отдельный столбец.
- [ ] Отсылки к Договору и к закону разнесены.
- [ ] Уровень определённости указан в каждом параметре.
- [ ] Ссылки на пункты есть в каждом параметре.

### 8.5. Уровни

- [ ] В таблицу сравнения попали **только параметры Уровня A**.
- [ ] Параметры Уровней B и C в таблицу **не попали**.
- [ ] Если задача — быстрая справка, ответ дан только по Уровню A.
- [ ] Если задача — полный отчёт, ответ дан по A + B + C.

### 8.6. Формат

- [ ] Единый шаблон для всех пунктов.
- [ ] Таблицы там, где это уместно.
- [ ] Ссылки на пункты в едином формате.
- [ ] Пометки об уровне регулирования.
- [ ] Указан источник и дата действия документа.
- [ ] **Конечный ответ соответствует разделу 14 ТЗ.**

### 8.7. Отсутствие правок

- [ ] Отчёт можно использовать без дополнительной проверки.
- [ ] Отчёт не содержит формулировок, требующих уточнения.
- [ ] Все спорные места прямо обозначены как спорные.

## 9. Формат вывода

### 9.1. Структура отчёта

1. **Титульный блок** (раздел 14.2).
2. **Таблица сравнения** (раздел 6.1 или 14.3).
3. **Текстовая часть** по Уровням B и C (раздел 14.5).
4. **Приложение** с самопроверкой (раздел 14.6).

### 9.2. Оформление

- Каждый пункт — отдельный блок.
- Внутри блока: ответ → условия → ограничения → ссылки.
- Таблицы — для перечней, сроков, лимитов.
- Единый стиль ссылок.

### 9.3. Язык

- Русский, юридически нейтральный.
- Без оценочных суждений.
- Без советов «как лучше».
- Без эмоциональных усилителей.

---

## 10. Ограничения

ИИ **не должен**:

- проверять документ на юридическую силу;
- сверять с другими редакциями;
- оценивать судебную перспективу;
- давать рекомендации по выбору условий страхования;
- добавлять нормы, которых нет в документе;
- использовать внешние источники, кроме тех, на которые прямо ссылается документ.
