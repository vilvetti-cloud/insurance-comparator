0. НАЗНАЧЕНИЕ ДОКУМЕНТА
--------------------------------------------------------------------------------

Настоящее ТЗ описывает полный, самодостаточный процесс подготовки
аналитического отчёта по произвольному нормативному документу (правила
страхования, договор, регламент, инструкция) на основе заданного перечня
вопросов.

ГЛАВНОЕ ТРЕБОВАНИЕ: отчёт должен быть самодостаточным — читатель, открывший
его, получает полный ответ по каждому вопросу без обращения к исходному
документу и без уточняющих вопросов.

Для этого ТЗ содержит:
- требования к входным данным;
- трёхуровневый перечень вопросов (A/B/C) с указанием, что попадает в
  таблицу, а что — в текст;
- правила анализа, исключающие типовые ошибки;
- обязательные блоки ответа по каждому параметру;
- единый формат таблицы сравнения (6 столбцов);
- образец конечного ответа (раздел 14);
- чек-листы самопроверки;
- формат вывода и шаблоны формулировок.


1. ВХОДНЫЕ ДАННЫЕ
--------------------------------------------------------------------------------

1.1. ОБЯЗАТЕЛЬНЫЕ

- Файл документа (PDF, DOCX, TXT или иной машиночитаемый формат).
- Название документа и, если применимо, редакция/дата вступления в силу.
- Перечень вопросов (см. раздел 3). Если перечень не задан — использовать
  типовой из раздела 3.

1.2. ОПЦИОНАЛЬНЫЕ

- Контекст: для какой цели готовится отчёт (юридическая проверка, сравнение,
  клиентская консультация).
- Ограничения: только текст документа, без внешних источников.

1.3. ТРЕБОВАНИЯ К ЧИТАЕМОСТИ

Если PDF содержит технические артефакты (битые символы, наложения), ИИ
обязан:
- игнорировать артефакты, не несущие смысла;
- не делать выводов на основе повреждённого текста;
- при необходимости указывать: «фрагмент текста нечитаем, вывод сделан по
  сохранившейся части».


2. МЕТОДОЛОГИЯ АНАЛИЗА
--------------------------------------------------------------------------------

2.1. ПРИНЦИП «ТОЛЬКО ТЕКСТ ДОКУМЕНТА»

ИИ отвечает исключительно на основе загруженного документа. Внешние знания,
другие редакции, судебная практика и общие представления о «стандартных»
условиях не используются.

2.2. РАЗЛИЧЕНИЕ УРОВНЕЙ РЕГУЛИРОВАНИЯ

Каждый ответ должен быть отнесён к одному из уровней:

- Прямо предусмотрено документом — «Предусмотрено» + пункт.
- Отнесено к другому документу (договору, полису, приложению) —
  «Определяется Договором» + указание, что именно.
- Прямо исключено — «Исключено» + пункт.
- Не упомянуто — «Прямо не упомянуто» + анализ ближайших по смыслу пунктов.
- Противоречие внутри документа — «Внутреннее противоречие» + оба пункта.

2.3. РАБОТА С «МОЛЧАЩИМИ» ПУНКТАМИ

Если вопрос не имеет прямого ответа:
1. Найти ближайшие по смыслу пункты (покрытие, исключение, ограничение).
2. Указать, что прямого ответа нет.
3. Не делать вывод «покрывается по умолчанию» и не делать вывод «исключено
   по умолчанию».
4. Дать корректную формулировку: «Прямо не упомянуто; решение зависит от
   обстоятельств и условий Договора».

Стандартная формулировка для «молчащего» пункта:
«Прямо не упомянуто. Ближайшие по смыслу пункты: [ссылки]. Автоматическое
покрытие (или исключение) не подтверждено. Решение зависит от обстоятельств
события и условий Договора.»

2.4. РАБОТА С ОТСЫЛКАМИ

Если документ отсылает к Договору, закону или иному акту:
- указать это;
- не подменять содержание отсылки своими предположениями;
- отметить, что параметр определяется соответствующим документом.

2.5. ТОЧНОСТЬ ФОРМУЛИРОВОК

- Использовать формулировки, близкие к тексту документа (особенно для
  порогов, сроков, лимитов).
- Различать «превышает», «равно или превышает», «не менее», «не более».
- Различать «страховая сумма», «страховая стоимость», «действительная
  стоимость».
- Различать «риск» и «страховой случай».
- Различать «рабочие» и «календарные» дни.

2.6. ССЫЛКИ НА ПУНКТЫ

Каждое утверждение сопровождается ссылкой в формате:
- «п. X.Y»
- «п. X.Y.Z»
- «пп. X–Y»
- «подп. N п. X.Y»


3. ПЕРЕЧЕНЬ ВОПРОСОВ И ЕГО УРОВНИ
--------------------------------------------------------------------------------

3.0. НАЗНАЧЕНИЕ ПЕРЕЧНЯ И ПРИНЦИП УРОВНЕЙ

Перечень вопросов не означает, что все вопросы должны попасть в таблицу
сравнения. Перечень — это каркас полноты. Он разделён на три уровня:

- Уровень A. Ключевые параметры — основа таблицы сравнения. Куда попадает:
  только в таблицу сравнения. Объём: 10 параметров.
- Уровень B. Существенные условия — полный отчёт, практические условия.
  Куда попадает: в текстовую часть отчёта. Объём: ~52 вопроса.
- Уровень C. Справочные условия — полнота отчёта. Куда попадает: в
  текстовую часть отчёта. Объём: ~50 вопросов.

Правила использования уровней:
1. Уровень A — обязателен для таблицы сравнения. Именно эти 10 параметров
   образуют строки таблицы.
2. Уровень B — обязателен для полного отчёта. В таблицу не попадает.
3. Уровень C — обязателен для полного отчёта. В таблицу не попадает.
4. Если задача — быстрая справка, допускается ответ только по Уровню A.
5. Если задача — полный отчёт, отвечать нужно на A + B + C, но таблица
   строится только из A.

Запрещено:
- впихивать в таблицу параметры из уровней B и C;
- отвечать только на «удобные» вопросы, пропуская остальные;
- считать, что весь перечень вопросов = строки таблицы.


3.A. УРОВЕНЬ A — КЛЮЧЕВЫЕ ПАРАМЕТРЫ (ДЛЯ ТАБЛИЦЫ СРАВНЕНИЯ)

Это 10 параметров, которые образуют строки таблицы. По каждому параметру
заполняются обязательные блоки (раздел 5 ТЗ) и столбцы таблицы (раздел 6).

A1. Франшиза — виды, размер, применение по умолчанию.
A2. Ремонт без справок — случаи, лимиты, ограничения.
A3. GAP — наличие, условия, лимит, варианты расчёта.
A4. Порог полной гибели — процент, варианты урегулирования.
A5. Самовозгорание — покрытие, исключения.
A6. Терроризм — покрытие, исключения, «молчащий» пункт.
A7. БПЛА / дроны — покрытие, исключения, «молчащий» пункт.
A8. Эвакуатор — лимит, количество, полное возмещение.
A9. Тип ремонта — форма возмещения, СТОА, износ, срок.
A10. Сроки выплаты / направления — сроки по основаниям, продление.

Формат вывода: таблица по форме 6 (6 столбцов).

3.D. СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ УРОВНЕЙ

Быстрая справка: только A. В таблице — 10 строк из A.
Полный отчёт: A + B + C. В таблице — 10 строк из A; B и C — в тексте.
Сравнение двух документов: A для обоих. Сопоставительная таблица по A.
Глубокий юридический разбор: A + B + C. Таблица из A; B и C — в тексте
с примечаниями.


4. ПРАВИЛА ФОРМИРОВАНИЯ ОТВЕТОВ
--------------------------------------------------------------------------------

4.1. СТРУКТУРА КАЖДОГО ОТВЕТА

Каждый ответ должен содержать:
1. Прямой ответ (одно предложение).
2. Суть условия (механизм).
3. Числовые параметры (сроки, проценты, лимиты).
4. Условия применения.
5. Ограничения и исключения.
6. Отсылки к Договору.
7. Отсылки к закону.
8. Ссылки на пункты.
9. Уровень определённости.

4.2. ШАБЛОНЫ ФОРМУЛИРОВОК

Прямое покрытие:
«Предусмотрено. [Условие]. Ограничения: [перечень]. Пункты: [ссылки].»

Определяется Договором:
«Предусмотрено как механизм, конкретные параметры определяются Договором.
[Что именно определяется]. Пункты: [ссылки].»

Прямое исключение:
«Исключено. [Формулировка исключения]. Применяется, если иное не
предусмотрено Договором. Пункты: [ссылки].»

Не упомянуто:
«Прямо не упомянуто. Ближайшие по смыслу пункты: [ссылки]. Автоматическое
покрытие (или исключение) не подтверждено. Решение зависит от обстоятельств
события и условий Договора.»

Внутреннее противоречие:
«В документе есть расхождение: п. X говорит [А], п. Y говорит [Б]. Для
корректного вывода необходимо [уточнение].»

4.3. ЗАПРЕЩЁННЫЕ ФОРМУЛИРОВКИ

- «Скорее всего, покрывается».
- «Обычно так и бывает».
- «По стандартным правилам».
- «Как правило, суды...».
- Любые утверждения без ссылки на пункт.
- Подмена «не упомянуто» на «исключено» или «покрыто».

4.4. ТОЧНОСТЬ ПО ЧИСЛАМ И СРОКАМ

- «Более 75%» не равно «75% и более».
- «Не более 25%» не равно «25%».
- «30 рабочих дней» не равно «30 календарных дней».
- «С даты предоставления документов» не равно «с даты обращения».
- «После получения результатов диагностики» не равно «с момента обращения».


5. ОБЯЗАТЕЛЬНЫЕ БЛОКИ ОТВЕТА (ДЛЯ КАЖДОГО ПАРАМЕТРА)
--------------------------------------------------------------------------------

Каждый ответ по каждому параметру обязан содержать следующие блоки. Если
блок неприменим — писать «Не применимо» или «Не установлено», но не
пропускать.

5.1. БЛОК 1. ПРЯМОЙ ОТВЕТ
Одно предложение: «Предусмотрено» / «Не предусмотрено» / «Прямо не
упомянуто» / «Определяется Договором» / «Исключено».

5.2. БЛОК 2. СУТЬ УСЛОВИЯ
Развёрнутое описание механизма: что предусмотрено, как работает, в каких
границах. 2–5 предложений, близко к тексту.

5.3. БЛОК 3. ЧИСЛОВЫЕ ПАРАМЕТРЫ
Все числа, сроки, проценты, лимиты, пороги. Если чисел нет — «Числовые
параметры в документе не установлены».

5.4. БЛОК 4. УСЛОВИЯ ПРИМЕНЕНИЯ
При каких обстоятельствах параметр применяется. Если условий нет —
«Применяется без дополнительных условий».

5.5. БЛОК 5. ОГРАНИЧЕНИЯ И ИСКЛЮЧЕНИЯ
Что не покрывается, изъятия, оговорки, запреты. Перечень. Если ограничений
нет — «Ограничения не установлены».

5.6. БЛОК 6. ОТСЫЛКИ К ДОГОВОРУ
Что именно определяется Договором. Если отсылок нет — «Определяется только
документом».

5.7. БЛОК 7. ОТСЫЛКИ К ЗАКОНУ
Ссылки на законы, прямо упомянутые в документе. Если отсылок нет — «Отсылки
к закону отсутствуют».

ссылка.

14.5. ТЕКСТОВАЯ ЧАСТЬ (УРОВНИ B И C)

Каждый вопрос раскрывается по 9 блокам раздела 5 ТЗ:

### [Номер]. [Формулировка вопроса]
- Прямой ответ: ...
- Суть условия: ...
- Числовые параметры: ...
- Условия применения: ...
- Ограничения и исключения: ...
- Отсылки к Договору: ...
- Отсылки к закону: ...
- Ссылки на пункты: ...
- Уровень определённости: ...

Если блок неприменим — писать «Не применимо» или «Не установлено», но не
пропускать.

14.6. ПРИЛОЖЕНИЕ С САМОПРОВЕРКОЙ (ОБЯЗАТЕЛЬНОЕ)

Формат:

## Приложение. Самопроверка
- [x] Ответы даны на все вопросы Уровней A, B, C.
- [x] По каждому вопросу заполнены 9 блоков.
- [x] Таблица сравнения построена только из Уровня A.
- [x] Формат таблицы — 6 столбцов (6.1).
- [x] В таблице нет пустых ячеек.
- [x] Числа и сроки соответствуют тексту документа.
- [x] «Молчащие» пункты обозначены как «Прямо не упомянуто».
- [x] Нет утверждений без ссылки на пункт.
- [x] Нет подмены «не упомянуто» на «исключено» или «покрыто».

14.7. ЧТО ЗАПРЕЩЕНО В КОНЕЧНОМ ОТВЕТЕ

Запрещено: таблица из 3 столбцов «Параметр / Док. 1 / Док. 2» без раскрытия
по столбцам. Почему: не соответствует 6.1.

Запрещено: ответ одной фразой в ячейке. Почему: потеряны ограничения и
условия.

Запрещено: пустая ячейка. Почему: читатель не понимает, нет данных или не
проверено.

Запрещено: утверждение без ссылки на пункт. Почему: нарушает принцип
«только текст документа».

Запрещено: смешение уровней A/B/C в таблице. Почему: нарушает раздел 6.3.

Запрещено: домыслы о покрытии/исключении. Почему: нарушает раздел 2.3.

Запрещено: подмена «не упомянуто» на «исключено». Почему: нарушает
раздел 2.2.

14.8. КРИТЕРИЙ ГОТОВНОСТИ КОНЕЧНОГО ОТВЕТА

Ответ считается готовым, если:
1. Есть титульный блок.
2. Есть таблица по 6.1, заполненная без пустых ячеек.
3. В таблице только Уровень A.
4. Есть текстовая часть по B и C, каждая — по 9 блокам.
5. Есть приложение с самопроверкой.
6. Отчёт можно использовать без обращения к исходному PDF.
7. Отчёт не требует последующих правок.
